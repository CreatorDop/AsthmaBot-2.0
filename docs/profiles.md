# Профілі та інтерфейс

| ID | Профіль | Поля/контекст щоденника |
|---:|---|---|
|0|Базовий|Симптоми, час, загальні обставини |
|1|Алергічна астма|Власні спостереження контактів з алергенами/сезону |
|2|Неалергічна астма|Холод, запахи та інші помічені тригери |
|3|Астма фізичного навантаження|Активність, час відносно симптомів |
|4|Кашльовий варіант|Час, тривалість і характер кашлю |
|5|Професійна астма|Зміна, вихідний, можливі експозиції |
|6|Нічні симптоми|Сон, пробудження, спостереження |

Профіль обирає користувач; пристрій не встановлює форму астми. Текст підказки й фільтр історії змінюються, датчик, пороги спроби й опір каналу — однакові. У браузері щоденник показує обраний профіль. Ліки та їх дозування не рекомендуються.

OLED: «Виміряти PEF», «Історія», «Мій профіль», «Дихальні вправи», «Bluetooth», «Налаштування». NEXT перегортає, OK обирає, BACK повертає/скасовує. Історія OLED показує останній результат; повний список — через BLE/USB. Це свідоме обмеження128×64 дисплея.

Смартфон: web/index.html — адаптивний прототип. Локально `python -m http.server 8000 --directory web`, відкрити localhost:8000 на цьому ж комп’ютері. Для Android через мережу потрібен HTTPS, звичайний http://IP комп’ютера не достатній для Web Bluetooth. Публічного хостингу не налаштовано. Можливість Bluetooth залежить від браузера; iOS-підтримку не обіцяємо [S24].

Графік, історія, фільтри, щоденник і CSV працюють без пристрою в DEMO. База прив’язана до джерела та calibrationID. Дані різних калібрувань не з’єднуються лінією. Веб-база локальна, базу самого ESP32 вводять через USB. Кольорові медичні зони не реалізовані; відсоток від бази — лише арифметика.

NasalTrack показує мВ; графік запитує їх5 разів/с. Це не гарантована рівномірна дискретизація: BLE додає затримку, тепловий відгук залежить від монтажу. Немає детектора апное або автоматичного підрахунку клінічної частоти дихання.
