# Прошивка й протокол

## Складання

Потрібні Python3, PlatformIO Core і USB-драйвер плати. З кореня репозиторію:

```sh
python -m pip install platformio
pio run -d firmware
```

platformio.ini фіксує espressif32@6.9.0, U8g2@2.36.5, ArduinoJson@7.2.1. Збірку виконано для esp32dev / ESP32-WROOM з4MB flash. Плати C3/S3 не взаємозамінні з цими GPIO й binary.

## Прошивання

Перевести SW1 у CHARGE, від’єднати зовнішній зарядний кабель і зняти JP1 між boost і5V DevKit. Не вимірювати дихання з під’єднаним USB. Підключити USB тільки до ESP32, потім:

```sh
pio run -d firmware -t upload --upload-port COM5
pio device monitor -d firmware --port COM5 --baud 115200
```

COM5 — приклад Windows; у Linux зазвичай /dev/ttyUSB0, вибрати фактичний порт. Якщо автоматичний boot не працює, тримати BOOT під час початку завантаження, відпустити після з’єднання. Після прошивання від’єднати USB, повернути JP1 і ввімкнути RUN. Вбудований `.bin` — результат компіляції, не доказ запуску на платі. Оновлення через USB реалізовано інструментами PlatformIO; OTA/відкат/підписані образи не реалізовані.

## Модулі

sensors: SDP810 continuous0x361E,9 байт із CRC8, шкала60, температура/200; measurement: незалежна від Arduino логіка калібрування й спроби; display: OLED/U8g2 кирилиця; bluetooth: BLE GATT, черга команд; profiles:7 профілів; storage:NVS96 записів; battery:ADC; diagnostics:індикація; main:меню й автомат станів.

Перед спробою: IDPeak, калібрування, справний сенсор, батарея й NVS. Нуль2s, щонайменше300 відліків, |mean|≤2Pa, SD≤0.2Pa. Це інженерні критерії прототипу. Збір5ms, перерва>25ms → TIMING. Початок≥15 л/хв; закінчення після300ms нижче5 л/хв або6s; очікування15s. Короткий пік<100ms/20 відліків, зворотний потік, NaN чи вихід із таблиці відхиляються. Ці пороги не взято за нормативні критерії якості PEF.

OLED і довгі BLE/NVS операції не виконуються під час збору. На OLED лишається екран запису; результат з’являється після завершення. Збереження — один CRC32-захищений слот NVS після спроби;96 слотів циклічно. Після перезапуску порядок відновлюється за sequence. Відключення живлення під час запису ще потрібно перевірити на платі. NVS, структура даних і прошивка не забезпечують криптографічної цілісності.

## Команди JSON, один рядок на команду

Через USB115200: `{"cmd":"status"}`, `{"cmd":"history"}`, `{"cmd":"raw"}`, `{"cmd":"nasal"}`, `{"cmd":"profile","id":0}`. Команда time має Unix epoch у секундах: `{"cmd":"time","epoch":1795305600}` — лише приклад, треба передати поточний час. Без синхронізації epoch=0; uptime зберігається окремо. Годинника RTC немає.

Калібрування, baseline та repeat_tolerance приймаються лише USB. Формати — у calibration.md. Профілі0…6. BLE не може запускати вимірювання, змінювати калібрування чи вмикати DEMO. DEMO вмикається фізично в меню й після перезапуску вимкнений.

Service: d0bb0001-86ce-4d45-8c2f-154a1cefe200; TX notify: ...0002...; RX write: ...0003.... TX передає JSON, розділений на20-байтні фрагменти, кінець повідомлення — newline. RX до191 байта; USB до1800. Перепідключення потребує повторного отримання GATT characteristics. BLE фізично не перевірено. Автентифікації/шифрування на рівні застосунку немає: тільки лабораторні анонімні дані.

Запис: type=record, seq, epoch, uptime_ms, pef, duration_ms, profile, module=2, demo, cal. Зміна калібрування скидає базу, а демонстраційні дані мають cal=DEMO-SYNTHETIC. Не видаляти цей маркер перед експортом.
